Hover Card

arrow_back arrow_forward

Norbielink has no hover card — no rich panel of content opens on hover anywhere in the product. What it does have is hover reveal: a card or row keeps its actions hidden until the pointer is over it, so a dense screen stays quiet. That pattern is documented here. For a short label on hover, see Tooltip.

Card action

An Edit button pinned to the card’s top-right corner, at zero opacity until the card is hovered. The card itself is the hover target, not the button — move the pointer anywhere over it.

Locked action

When the action is not permitted the button still appears on hover, disabled, and carries a second hover target of its own: hovering the button reveals a dark bubble explaining why. Two nested hover scopes, which is as close as the product gets to a hover card.

Row swap

On a list row the reveal is a swap: the trailing status check fades out as the remove button fades in, in the same place. The row never changes width, so nothing shifts. This list lives on a tinted #F5F6F8 rail, which is what lets both the #F0F1F4 hover and the white selected row read — on a white surface neither would.

Hover reveal is for a secondary action on a repeated element. A primary action is never hidden behind hover — it sits in the toolbar above the list.
Because reveal is opacity-only, the hidden button still occupies its box and is still focusable. It is a visual affordance, not a gate.
None of this works on touch. Every revealed action has a non-hover route to it — opening the record, or the row’s context menu.
The locked bubble is the product’s only nested hover scope: the card reveals the button, then the button reveals the bubble.
